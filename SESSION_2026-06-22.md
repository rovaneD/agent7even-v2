### 4. Webhook — Convoy signature format fix

**Root cause:** OpenRouter delivers webhooks via **Convoy** (webhook delivery service, `User-Agent: Convoy/v26.3.5`). Convoy JSON-minifies the body before signing. Our handler computed `HMAC(secret, rawBody)` but needed `HMAC(secret, minify(body))`.

Convoy supports two signature formats:
- **Simple:** `<hex>` — HMAC over minified body
- **Advanced:** `t=<timestamp>,v1=<hex>` — HMAC over `"<timestamp>,<minifiedBody>"`

Updated `verifySignature()` in `app/api/webhooks/openrouter-video/route.ts` to handle all three cases: advanced (timestamp-prefixed), simple (minified body), and raw-body fallback.

**Effect:** 401s stopped. Webhook calls now pass signature verification.

### 5. Webhook — Convoy data envelope fix

**Root cause:** Convoy wraps the OpenRouter event in a `{ data: {...} }` envelope. Our handler read `payload.id` (undefined); correct path is `payload.data.id`.

Updated `handleVideoWebhook()` to extract `inner = payload.data ?? payload` and read all fields (`id`, `status`, `unsigned_urls`, `error`) from `inner`.

Added `payload keys:` debug log (key names only, no values) for future shape debugging.

### 6. Video download — Bearer token fix

**Root cause:** OpenRouter's `unsigned_urls` field is misnamed — they are NOT publicly accessible. They require `Authorization: Bearer <OPENROUTER_API_KEY>` just like any other OpenRouter API call. A plain `fetch(videoUrl)` returns 401.

Fixed by passing `openRouterHeaders()` to the download fetch in both:
- `app/api/webhooks/openrouter-video/route.ts`
- `app/api/posts/reconcile-video/route.ts`

### 7. Reconciliation endpoint

`POST /api/posts/reconcile-video` — polls OpenRouter for all `running` video tasks belonging to the authenticated user. For each completed job: downloads video (with Bearer auth), uploads to `post-assets`, inserts `agent_outputs` as `pending_approval`, marks task `completed`.

401/403 on download → marks task `failed` immediately (URL expired — ~2hr TTL).
Other errors → leaves as `running` (video may still be generating).

Called:
- On `ApprovalsClient` mount (auto-check for stuck jobs)
- From "Check if ready" button in `PostVideoGenerate` pending state

### 8. Approval queue — video generating card
