## Code changes (8aa8719)

### 1. Canonical profile resolution everywhere

All profile reads by Clerk user now use `resolveClerkProfile` (`lib/profiles/resolveClerkProfile.ts`), matching the house idiom (inline generic includes the canonical fields; no email fallback added, so behavior is unchanged for single-profile users):

- **Dashboard pages (8):** foundation, team, support, inbox, deliverables, ai-toolkit, notifications, services/inquiry
- **API routes (~25):** foundation/* (9), brand/* (3), team/* (3), support/* (3), maya/campaign + task-complete, inbox/draft-reply, deliverables/upload, post-assets/download, ai/run-prompt + save-prompt, campaigns/generate, orders/complete- + delete-self-serve, notifications/mark-read, services/inquiry
- **Lib + webhook:** `lib/activity.ts` (`trackActivity`), `app/api/webhooks/stripe/route.ts` (both `.single()` reads; the lookup-by-`stripe_subscription_id` branch and the bulk `.update().eq('clerk_user_id')` writes were left as-is)

`grep` for the forbidden pattern now returns **zero** hits in `app/` and `lib/`.
