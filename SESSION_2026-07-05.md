## Critical fixes

### Team invite acceptance auth

- `GET /api/team/accept` no longer mutates an existing profile from an invite token alone.
- Existing-profile invite acceptance now requires a signed-in Clerk user whose email and `clerk_user_id` match the invited profile.
- Logged-out existing users are redirected through `/sign-in` with a safe relative `redirect_url` back to the accept route.
- `POST /api/team/invite` no longer returns `invite_token` in its JSON payload.

### Assignment start race

- `/api/agents/tasks/[id]/start` now conditionally claims assignments with `status = 'pending'` and `started_at IS NULL`, setting `status = 'running'` before dispatch.
- A second concurrent start returns `409` instead of dispatching a duplicate agent run.

### Owner-only approvals

- Approval queue list, single approve/reject, and bulk approve/reject APIs now reject team members with `403`.
- `/dashboard/agents/approvals` redirects team members to the dashboard.
- This matches `TEAM_WORKSPACE_SPEC.md`: members draft/run; owner approves anything that publishes or spends.
