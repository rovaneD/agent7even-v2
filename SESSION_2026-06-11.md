## Critical discovery — upload contamination

### What went wrong

- **Ingest alone was safe** — `POST /api/foundation/ingest` writes only to
  `foundation_knowledge` (+ `profiles.updated_at`). Identity untouched at upload.
- **Review Findings “Save N items” was the bug** — `UploadCard.handleSave` in
  `FoundationHub.tsx` POSTed checked extractions to `/api/foundation/save-answers`,
  merging competitor/reference text into `foundation_answers` and legacy columns
  (`ideal_customer`, `competitors`, etc.).
- **Impact:** User could silently replace their real business identity by saving
  fields extracted from a competitor URL/PDF. Confirmed in production before fix.
- **Recovery before undo:** Near-miss caught when Intelligence tab still showed
  pre-contamination answers in an open browser tab while DB had already been
  overwritten — underscored need for automatic snapshot + restore.

### Piece 1 — sever upload → identity (shipped)

| Commit | Summary |
|--------|---------|
| `b9fac70` | Stop upload Review Findings from overwriting Foundation identity |

**Fix:**

- `handleSave` PATCHes `foundation_knowledge.confirmed_fields` via ingest row id
  — never calls `save-answers`.
- New `PATCH /api/foundation/knowledge/[id]` — updates `confirmed_fields` only;
  does not touch `profiles`.
- Copy fix: Knowledge tab no longer claims “Maya pulls from these…” (Maya does
  not read knowledge yet).

**Remaining legitimate `save-answers` caller:** Intelligence section editor
(`saveEdit` in `FoundationHub.tsx`) — deliberate user identity edits only.

## Piece 1b — single-slot undo (shipped)

| Commit | Summary |
|--------|---------|
| `0ce8b1a` | Add reversible one-slot undo for Foundation identity answers |
| `ca3f109` | Fix Foundation restore button label and snapshot time subline |

**Schema (manual Supabase — not auto-applied):** `11_foundation_answers_snapshot.sql`

```sql
ALTER TABLE public.profiles
  ADD COLUMN IF NOT EXISTS foundation_answers_previous jsonb,
  ADD COLUMN IF NOT EXISTS foundation_answers_previous_at timestamptz;
```

**Helper:** `lib/foundation/answersSnapshot.ts`

- `buildIdentityUpdateWithSnapshot()` — capture current answers into previous
  slot, then apply patch
- `buildIdentityRestoreSwap()` — atomic reversible swap (restore does **not**
  capture)

**Restore route:** `POST /api/foundation/restore-previous`

**UI:** StrengthCard “Restore version from {time}” with confirm + rescore prompt

### Snapshot capture policy (final)

| Route | Captures snapshot? |
|-------|-------------------|
| `POST /api/foundation/save-answers` | **Yes** — section editor |
| `POST /api/foundation/save-exa-confirm` | **Yes** — Exa onboarding replace |
| `POST /api/foundation/score` | **No** — rescore must not consume undo slot |
| `POST /api/foundation/restore-previous` | **No** — swap only |
| Ingest / knowledge PATCH | **No** — never writes identity |

**Verify flow:** Edit section → Save (snapshot = pre-edit) → Rescore (snapshot
unchanged) → Restore → returns pre-edit answers.
